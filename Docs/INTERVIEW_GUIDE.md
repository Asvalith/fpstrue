# FPS 项目讲解：多人战斗、群体协作与性能归因

以当前多人分支为准。先讲正常流程，再用一个实际问题解释边界，不逐个背类名或 Guard。

## 1. 项目介绍

基于 UE5.5、C++ 与蓝图独立实现多人 FPS，完成装备、射击换弹、伤害死亡、重生与敌人战斗。重点做了逐发同步与预测校正、多人目标下的围攻调度，以及固定 160 AI 场景的线程/模块分析。

讲解顺序：**战斗链保证一致性 → 群体管理协调稀缺资源 → 两端独立性能分级 → 采集验证工作去了哪里。**

## 2. 架构：谁拥有状态，谁消费结果

| 所有者 | 唯一职责 | 不负责 |
| --- | --- | --- |
| GameMode | 接纳、出生/重生、计分、敌人人口、围攻管理器与离线保留 | 每次射击、动画和 UI 计算 |
| Character / Controller | 输入、组件协调、玩家控制与 AI 上下文 | 另存弹药、授予攻击许可 |
| ASC / GA | 激活、互斥、取消和动作任务 | 第二套弹药状态机 |
| WeaponComponent | 弹药、逐发队列、命中执行、唯一换弹时钟 | 依赖客户端动画决定结算 |
| AttributeSet / Health | 生命数值提交与伤害事件 | HUD 镜像反向决定血量 |
| SurroundManager | 站位归属、FIFO 晋升、攻击许可与寻路提交预算 | 个体感知、路径搜索算法 |
| 本地表现 | 插值、动画、声音、粒子和 HUD | 权威伤害、AI 行为和命中规则 |

Data Asset 配置共享，运行状态不共享。C++ 与蓝图通过函数、委托和实际接线的表现事件交互；没有消费者的钩子不继续保留。行为树资产共享，每个 Controller 的黑板和运行状态独立；缓存 KeyID，仍用 UE 黑板，不另写 ECS 容器。

## 3. 亮点一：逐发射击不只是一个开火 RPC

```text
输入 → Fire GA → 本地预测弹药、枪声与后坐力
     → 有界不可靠批次（真实武器、装备代际、会话、ShotId、时间、方向）
     → 8发重排窗 → 原服务器准入/执行队列 → 执行时复核
     → 扣弹/命中/伤害 → 最近4条裁决快速窗口 + 可靠终结兜底
     → 按快照水位消账与校正
```

- 入队和执行是两个时点，期间可能死亡、换枪或过期，不能为减少判断删除执行复核。
- 丢包诊断确认同通道可靠队头阻塞后，逐发常规输入改为有界不可靠批次；快速结果顺带最近裁决，可靠回执兜底。激活与低频结束控制仍可靠，尚不能保证极端激活等待下零丢发。普通松开的尾发与强取消分别处理，不把清账成功算作没有丢失输入。
- 同一 Shot 不重复扣弹/伤害；已准入未执行请求不能提前被当成最终拒绝。
- 弹药/备弹只发拥有者；观察者只需装备和动作。逐发结果不再重复塞入快照。
- 方向量化、SavedMove 自定义 bit 复用 UE 原生机制；没有使用 Protobuf，也没重写传输层。
- 换弹本地预测表现，服务器确认接管原 Montage 实例；唯一事务时钟完成装弹，结束晚到或被替换不成为第二个装弹入口。
- 同一探测分别估计动态 RTT/抖动与服务器时钟偏移。拥塞样本可更新 RTT，但不拖偏优质时钟；乱序、重复与过期均有回归，服务器继续独立校验输入时间。

取舍：弹药是武器业务计数，普通复制与逐发确认满足需要；GAS 管动作与预测上下文，不要求所有数值都成为 Attribute。激活版本、ShotId、ReloadId 分别保护不同事务，不是给每个函数重复加锁。

源码：[武器执行与复制](../Source/fpstrue/Weapons/fpstrueWeaponComponent.cpp)、[GAS 动作](../Source/fpstrue/Weapons/fpstrueCombatAbilities.cpp)、[移动与历史命中](../Source/fpstrue/Characters/Player/)。

## 4. 亮点二：站位、出手和导航分开

```text
感知获得目标 → Controller 写黑板 → 行为树选择行为
  → 目标玩家的 SurroundManager 登记参与者/保留 FIFO 排位
  → 获得内圈、外圈或外围候场目标 → Controller 发 MoveTo
  → 内圈且满足真实距离/朝向/遮挡 → 申请单次攻击许可
  → Combat 攻击；结束归还许可，死亡/退出/失败另回收站位
```

- 每目标 8 内圈 + 12 外圈；单次攻击候补上限 8，不是所有空间参与者上限。默认同时攻击预算也是 8；低于内圈人数时才产生该预算的候补竞争。
- **空间圆环不是环形队列**：槽位数组保留稳定 SlotId，释放时清占用，不删除数组元素让全员换位。FIFO 管晋升次序，逆向映射管占用归属。
- 服务器 AI 与管理器在 Game Thread 直接调用；同帧请求顺序处理，不额外发 Server RPC 或加多线程锁。提交状态后才通知。
- UE 行为树按搜索、活动节点和事件重评估运行，不是每帧从根完整遍历。此项目用间隔决策、初始错峰和事件唤醒；Controller 不再并行维护另一套行为选择器。
- 共享 EQS 筛候选，个体路径由原生导航处理。复用、退避和 World 帧预算减少提交次数，不是自写 A*。
- 失败释放席位、退避 1 秒后回队；8 秒无进展也回收。旧回调不能撤销新席位。

边界：外圈 NavMesh 投影不足以证明胶囊站得下，未做同等间距检查；失败回队尚不记住坏槽或不可达敌人-槽位组合。应补候选有效性与短期排除，不改环形插删、不再增加管理器。已有槽位测试固定导航输出，不能冒充墙角动态障碍验收。

源码：[群体管理器](../Source/fpstrue/Characters/Enemies/AI/fpstrueSurroundManager.cpp)、[行为树](../Source/fpstrue/Characters/Enemies/AI/fpstrueEnemyBehaviorTree.cpp)、[EQS](../Source/fpstrue/Characters/Enemies/AI/fpstrueEnemyPositionQuery.cpp)。

## 5. 亮点三：两端分级，再验证实际消费者

服务器缓存有效玩家和敌人位置，以最近玩家距离及战斗事实计算 Gameplay Significance，应用决策/移动/复制策略，不按相机停 AI。客户端读取相机快照，独立算 Render Significance，分配模型、阴影和光追预算，接入动画共享和降频。评分/档位不跨网同步，复制的是玩法事实。

敌人用六个根变换驱动的查询盒，解除普通敌人对完整骨骼 PhysicsAsset 刷新的依赖，保留必要攻击姿态保护。代价是命中区域不逐骨骼贴合手脚。RenderTier 不改变服务器命中规则，不用距离让命中形状突然切换。

排查顺序：**同构建/同场景 → 预热和人口门禁 → 对齐完整帧 → GT CPU 与节拍 → 模块调用树 → 拆等待中的嵌套工作 → 单变量对照。**

2026-10-24 最后一次 160 AI、2 玩家、约 62 秒 Editor Trace：

| 观察 | 结果与含义 |
| --- | --- |
| 专服帧间隔 / GT 实际 CPU | 33.16 / 12.16 ms；30 Hz 节拍空闲约 20.70 ms，不是 33 ms 都在计算 |
| 专服调用范围 | CMC 3.26 ms、TickFlush 2.37 ms、骨骼组件 Tick 1.64 ms；scope 不与嵌套子项重复相加 |
| Sig / 选点验证 | 协调更新 0.028 ms、EQS 位置测试 0.010 ms；没有证据值得先改 SIMD/空间哈希 |
| 渲染客户端 | 平均帧 11.07 ms，P95 12.61、P99 13.96；GT 实际 CPU 8.52 ms |
| 客户端线程 unit | RT 8.03、RHI 8.94、GPU 6.97 ms；计数可能滞后，不能相加成整帧 |
| 当前等待入口 | RT 动态网格收集约 1.68 ms；RHI Submission_Wait 约 1.07 ms，不能套用旧遮挡等待结论 |
| 动画实际执行 | 客户端有 Worker 动画事件、133～136 个共享跟随者；专服性能线程总开关 false，没有相应 Worker 动画事件 |
| Gameplay LOD | 首尾 156 个因距离仍为 Full；不代表客户端渲染降级和动画共享失效 |

历史上追过渲染等待到遮挡结果读取，也做过决策、动画与场景优化对照；必须带原实验条件讲，不把不同构建百分比拆成当前整帧贡献。本轮只有一次诊断，未做 OS Ready/Blocked 调度归因或 Shipping 运行。

源码：[分级与动画共享](../Source/fpstrue/Characters/Enemies/Performance/fpstrueEnemyPerformance.cpp)、[采集工具](../Tools/Performance/)、[历史原始证据索引](../PERFORMANCE_EVIDENCE.md)。

## 6. 面试时能承诺到哪里

- 当前完整回归 99 项通过但有 13 项警告；槽位专项 5 项通过但有夹具警告。
- 正常本地射击/恢复通过；严格弱网零拒绝门禁未通过。没有未结账本不等于体验通过。
- 没承诺公网、跨服恢复、新 Shipping 帧率、完整发布包或任意复杂地形下 160 敌人稳定。
- 能解释状态归属、减少重复工作、用失败记录修正结论；不把原生插件说成自研底层系统。

完整结果和未闭环项以 [验收记录](REFACTOR_ACCEPTANCE.md) 为准。
